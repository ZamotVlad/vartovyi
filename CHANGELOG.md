# Журнал змін

Кожен крок - окремий коміт (або кілька) у `main`. Формат - Conventional Commits.

## 1.16 - швидкодія і SEO
- `GET /api/v1/monitors` повертає `latest_check` для кожного монітора одним SQL-запитом
  (`DISTINCT ON`). Дашборд більше не робить N окремих запитів
- `robots.txt` (закриває `/api/` і `/dashboard`) і `sitemap.xml` з публічними сторінками
- `meta description` на публічних сторінках, `canonical` на лендінгу, `noindex` для дашборду

## 1.15 - візуальна поліровка
- Лендінг «вмикається як пульт»: рядки з'являються по черзі, лампи спалахують
- Лампи зі світінням через `@property --glow`, поверхні з легким градієнтом
- Липка шапка з `backdrop-filter`, тінь при скролі через `animation-timeline: scroll()`
- Підсвітка рядка через `:has()`, об'ємні кнопки, власний перемикач `role="switch"`
- View transitions між сторінками, HTML-сторінки 404 і 500 (API лишається на JSON)
- `og:image`, `apple-touch-icon`, `theme-color`; усе вимикається при `prefers-reduced-motion`

## 1.14 - веб-інтерфейс
- Лендінг, вхід, реєстрація, дашборд моніторів на чистих HTML/CSS/JS
- Спільний клієнт `api.js`: токени, тихий refresh, редірект на `/login`
- Валідація на клієнті, помилки мережі й сервера показуються як частина UI
- Локальні шрифти: Space Grotesk + Manrope для кирилиці, IBM Plex Mono для даних

## 1.13 - сторінка статусу і документація
- `status_slug` у користувача, `is_public` у монітора, `GET /api/v1/status/{slug}`
- Uptime 24 год / 7 днів / 30 днів рахується агрегацією в PostgreSQL
- README з архітектурними схемами, DECISIONS.md з трьома ADR

## 1.12 - тести
- Автоматична перевірка доступу: кожен маршрут з OpenAPI або захищений, або явно публічний
- Тести lifespan, логування, планувальника, налаштувань; покриття 99%
- fix: logout перевіряє токен до валідації тіла (раніше віддавав 422 замість 401)

## 1.9 - помилки
- Категорії доменних помилок (NotFound, Conflict, Authentication...), статус визначається в шарі API
- Єдиний формат тіла помилки, глобальні exception handlers

## 1.8 - рушій перевірок
- `httpx.AsyncClient` один на процес, `TaskGroup` + `Semaphore`, `asyncio.timeout()` на перевірку
- Класифікація збоїв (timeout, DNS, TLS, з'єднання), інциденти після N падінь поспіль
- Планувальник у lifespan, ендпоінти «перевірити зараз» та історія перевірок

## 1.7 - CRUD моніторів
- Пагінація, фільтри, сортування, ізоляція за власником (чужий монітор - 404)

## 1.6 - middleware
- Request id через contextvars, час обробки, JSON-логи, перехоплення 500, CORS

## 1.5 - автентифікація
- JWT access + refresh з ротацією, відкликання через Redis, API-ключі

## 1.4 - база даних
- Моделі SQLAlchemy 2.0, async-сесія, Alembic, репозиторії
